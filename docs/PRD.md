# PRD — Weibo Reader（Windows Web 版）

| 项 | 内容 |
|---|---|
| Language | 中文 |
| Project Name | weibo_reader_web |
| 编程语言/技术栈 | Node.js 内置模块（零第三方依赖）+ 原生 HTML/CSS/JS，无构建步骤 |
| 原始需求 | 将 macOS 原生应用 Weibo Reader 复刻为 Windows 本机可用的 Web 版：本地归档微博互动数据并进行离线检索/阅读/报告/订阅巡检 |
| 版本 | v1.0（首版可交付） |

## 1. 产品定义

**一句话定位**：一个跑在 Windows 本机浏览器里的微博互动数据归档与离线阅读工具——付费取数一次，之后搜索、阅读、出报告全部免费且离线可用。

**产品目标（正交）**
1. **数据归自己**：把「发出的评论 / 收到的评论 / 被@ / 用户微博 / 博文评论」落到本地 `data/`，断网可读。
2. **取数可控可算**：任何一次取数在开始前就能看到条数上限、日期范围与 credits 估算，历史已存数据复用为 0 credits。
3. **阅读与输出闭环**：本地搜索 → 未读标记 → 离线 HTML 报告（含未读高亮）→ 订阅定时巡检。

**非目标（Out of Scope）**：发帖/评论/点赞/删除等任何微博写操作；多用户/多账号体系；云端同步；移动端适配；数据可视化大屏。

## 2. 目标用户与用户故事

**目标用户**：需要一个「不受微博客户端时间线、搜索限制、内容消失影响」的长期留存者——包括做内容/舆情观察的运营与研究者、关注特定账号互动的重度用户、以及需要给他人交付静态证据文件的人。

- **US-1（归档）**：作为重度微博用户，我想把某个账号的历史评论与@记录一次性拉进本地，这样对方删帖后我仍可回查。
- **US-2（检索）**：作为内容研究者，我想用关键词 + 作者 + 日期区间在本地交叉过滤，这样不必为每次搜索重复付费。
- **US-3（输出）**：作为运营，我想把某用户某时间段整理成一份离线 HTML 报告发给同事，这样对方无需安装任何东西就能看到带未读高亮的原文。

## 3. 需求池

> 优先级：P0 = 必须（首版交付，缺一不可）；P1 = 应该（首版内尽量）；P2 = 可延后。
> 「演示数据」= 无网络 / 无 token 时，服务端以 `DEMO_MODE` 提供内置示例用户、博文、互动与订阅日志。

### P0 — 账户与离线可用

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-01 | 启动即用 | 执行 `node server/server.js` 后终端打印 `http://127.0.0.1:7788`；浏览器打开首页 ≤1s 内出首屏，无构建、无 `npm install` 第三方包 |
| P0-02 | 浏览器授权登录 | 点「登录微博」→ 展示设备码与校验链接 → 轮询 `/oauth/token` 成功后写入 token 并展示昵称/UID；二维码或链接可在新标签打开 |
| P0-03 | 手动 token 兜底 | 设置页可粘贴 access token 保存；保存后立刻校验 `/oauth/userinfo`，失败给出明确错误文案且不覆盖旧 token |
| P0-04 | 账户与余额 | 顶栏常显「剩余 credits」，来源为 CLI 账户接口；刷新按钮可手动重取；接口异常时显示上次缓存值 + 时间戳 |
| P0-05 | 离线演示模式 | 无 token 或 `DEMO_MODE=1` 时，横幅提示「演示数据，不含真实账号」；用户库/博文库/搜索/报告/订阅页均有数据可操作，且不发起真实付费接口调用 |
| P0-06 | 退出登录 | 清除 token 与登录态，不影响本地已归档数据；退出后自动进入演示模式 |

### P0 — 归档对象管理

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-07 | 添加用户 | 支持粘贴 `weibo.com/u/xxxx`、`weibo.com/昵称` 主页链接或纯数字 UID；解析失败提示「无法从该链接识别 UID」；重复添加不产生重复记录 |
| P0-08 | 用户列表 | 展示头像/昵称/UID/已存条数/未读数；支持按昵称或 UID 搜索（即时过滤，0 credits）；支持「特别关注」标记并置顶 |
| P0-09 | 添加博文 | 支持粘贴博文详情页链接或微博 ID；添加仅创建记录，**不自动取评论**；列表中未取数的博文显示「尚未获取评论」 |
| P0-10 | 博文列表 | 展示作者/正文摘要/发布时间/已存评论数/收藏状态；支持收藏筛选 |

### P0 — 付费取数（核心）

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-11 | 内容模式 | 提供 7 种模式：发出+收到评论 / 发出的评论 / 收到的评论 / 被@的评论 / 被@的微博 / 用户微博 / 某博文下评论；选择模式后表单字段随之变化 |
| P0-12 | 范围与条数 | 可填条数上限；可填起止日期，允许只填一端，且「包含所选当天」（结束日按 23:59:59 处理）；日期非法/倒置时禁止提交并给出原因 |
| P0-13 | 增量与历史 | 支持「增量更新」（从本地已有最晚日期续拉）与「历史分页」（向前翻页）；已存在记录本地复用，重复区间不重复计费 |
| P0-14 | gap 待补区间 | 互动时间轴标出本地已存日期与待补区间，点击待补区间可一键预填取数表单 |
| P0-15 | 缺失正文提示 | 已知 ID 但正文缺失的记录单独列「缺失正文」清单，提示可单独补取，且不计入互动统计 |
| P0-16 | 任务面板 | 运行时展示：进度条、接口累计返回条数、credits 消耗估算、剩余余额、运行日志（逐行滚动）；有「开始读取」「停止读取」按钮；停止后已落盘数据保留 |
| P0-17 | 额度不足保护 | 估算消耗 > 剩余余额时，开始按钮禁用并提示差额；运行中余额跌破预估则自动停止并写明中断原因 |
| P0-18 | 0 credits 复用 | 对同一区间二次执行时，命中本地缓存的记录条数不计费；界面明确标注「复用本地 X 条 / 新增 Y 条」 |

### P0 — 阅读与搜索

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-19 | 用户详情 | 展示本地互动三类分组（发出 / 收到 / 被@）与时间轴；点击任意日期可看当天记录；未读记录有视觉标记 |
| P0-20 | 已读动作 | 单条或按分组「标记已读」；未读数随之更新且刷新页面后保持（落盘） |
| P0-21 | 全局搜索 | 关键词在正文中匹配；可叠加作者、所属对象（用户/博文）、日期区间三个筛选，条件取交集；0 credits；结果分页（每页 20 条），显示命中总数与耗时 |
| P0-22 | 空结果友好 | 无命中时展示「无结果」+ 当前生效筛选条件摘要 + 一键清空筛选 |

### P0 — 报告

| ID | 需求 | 验收标准 |
|---|---|---|
| P0-23 | 生成 HTML 报告 | 针对某用户或某博文，可设条数上限或日期范围，生成静态 HTML 到 `data/reports/`；接口返回 `{path}`，前端提供「打开报告」（调系统默认浏览器）与「复制路径」 |
| P0-24 | 报告唯一性 | 每位用户 / 每条博文各只保留最新 1 份，重新生成覆盖旧文件，磁盘上同名目录下 ≤1 个 html |
| P0-25 | 未读高亮 + 精确已读 | 报告中未读记录高亮；生成时返回待标记记录 ID 列表，**仅当**前端确认浏览器已接收（前端回调成功）后才把这些 ID 标记为已读；回调失败则保持未读 |
| P0-26 | 报告内容 | 含标题（对象+时间范围+生成时间）、记录正文、作者、时间、原博文链接；不含 token、余额等敏感信息 |

## 4. 页面 / 信息架构

```
顶栏（全局）：产品名 | 剩余 credits ⟳ | 登录态/演示模式徽标 | 全局搜索框
├─ /                总览：余额、今日消耗、未读总数、最近任务、快捷入口
├─ /users           用户库：列表 + 搜索 + 特别关注 | → /users/:uid 用户详情
│                    用户详情：概览 / 互动分组（发出·收到·@）/ 时间轴(gap) / 生成报告 / 订阅
├─ /posts           博文库：列表 + 收藏 | → /posts/:id 博文详情（评论列表 / 报告 / 订阅）
├─ /fetch           获取数据：模式选择 → 对象 → 范围 → 预估 → 运行（任务面板 + 日志）
├─ /search          全局搜索：关键词 + 作者 + 对象 + 日期 → 分页结果（0 credits）
├─ /subscriptions   订阅：订阅列表 + 状态控制 + 每轮上限 + 每日预算 + 日志
└─ /settings        设置：账户与登录 / 数据目录 / 导入导出 / 费用参考 / 演示模式
```

导航常驻左侧边栏（6 项），详情页为二级路由，面包屑返回列表。

## 5. 关键交互与状态

| 场景 | 表现 |
|---|---|
| 未登录 | 顶栏显示「未登录 · 演示模式」；付费接口按钮统一禁用，hover 提示「需登录后使用」；阅读/搜索/报告/订阅配置仍可完整体验 |
| 首次打开（空库） | 用户库与博文库展示引导卡：①粘贴链接添加 ②或「载入演示数据」 |
| 加载中 | 列表用骨架屏，操作按钮进入 loading 态并禁用防重复提交；取数任务为长任务，以进度条 + 日志行流式呈现 |
| 错误 | 统一错误条：`错误码 + 人话原因 + 重试按钮`；区分「网络失败 / token 失效（引导重新登录）/ 额度不足 / 参数非法」四类文案 |
| 额度不足 | 预估阶段即拦截（禁用开始）；运行阶段中断则保留已落盘数据并写明「已花 X，剩余 Y」 |
| 部分成功 | 分页中途失败：保留已获取数据，标记「区间不完整」，时间轴上该区间继续显示为待补 |
| 报告已读回调 | 生成成功后前端 GET 报告 URL 确认 200 才提交已读；提交失败弹出「报告已生成，但已读状态未更新」并可重试 |
| 订阅预算耗尽 | 订阅卡片变灰，状态「今日额度用尽 · 明日自动恢复」+ 「重置额度」按钮 |

## 6. 数据与隐私边界

- **全本机**：所有数据落在 `data/`（`users.json`、`posts.json`、`records/*.jsonl`、`reports/`、`subscriptions.json`、`settings.json`）。无云端、无第三方分析、无外链字体/CDN。
- **仅监听回环**：HTTP 服务绑定 `127.0.0.1`，不监听 `0.0.0.0`；无跨域开放。
- **token 边界**：token 仅存本机 `settings.json`（不进数据包、不进报告、不打日志）；出站请求仅两条域名——`open.weibo.com`（登录/CLI 网关）与头像图片域名；前端接口响应中的 token 一律脱敏为 `***`。
- **报告是静态文件**：纯本地 HTML，不引用外部资源、不含脚本回连，可离线打开/邮件转发。
- **只读工具**：不调用任何写接口（发帖/评论/删除/关注）。
- **数据包可携带性**：导出 JSON 不含登录态、订阅、备注、已读状态，避免把身份信息带出。

## 7. 待确认问题（含默认假设）

| # | 问题 | 默认假设（按此实现） |
|---|---|---|
| Q1 | 订阅巡检是否需要常驻后台（关浏览器仍运行）？ | 是，定时器跑在 Node 进程内；关闭终端进程即停止（与原应用「退出即停止」一致） |
| Q2 | credits 单价的真实数值与接口是否稳定可查？ | 以内置价目表为默认，运行时「查询最新单价」成功则覆盖；失败回落到内置值 |
| Q3 | 演示数据是否允许写操作（生成报告/订阅会写盘）？ | 允许，但落在 `data/demo/` 子目录，不污染真实数据目录 |
| Q4 | 「被@的微博」与「用户微博」是否需要正文落库（会显著增加体积）？ | 需要，正文按需截断到 2000 字符，超长标记「已截断」并提供原链接 |
| Q5 | 是否需要 Windows 开机自启/托盘？ | 不需要（首版不做），仅提供 `node server/server.js` 手动启动 + 可选 `.bat` 双击脚本 |
